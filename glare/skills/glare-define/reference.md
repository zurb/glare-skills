# Define — Compressed (v1.1 + patterns v1.0, 2026-05-11)

## What this block is about

Define is the first (and foundational) facet of Glare — the "Credibility" facet. Its job is to slow teams down just long enough to agree on what matters before they start building. Define answers five questions: (1) What do users actually need? (2) Who are we designing for? (3) What recurring situations keep producing the same behavior? (4) Where will the evidence come from? (5) How will we know it worked? It does this through **five** building blocks — **User Needs, Audience, Patterns, Collecting Data, and UX Metrics** — that turn opinions, hunches, and vanity dashboards into testable signals.

> **Note on the Patterns block (added 2026-05-11).** The Define Overview source doc (v1.1, Oct 25, 2025) still describes four blocks. The marketplace structure was extended on 2026-05-11 with a fifth block — Patterns — sourced from its own v1.0 doc ("Glare | Define, Patterns v1.0," 2026-05-10). Patterns is now treated as a peer of the original four. Until the Define Overview doc is re-edited, treat the v1.0 Patterns doc as canonical for that block and this skill as the integration point. The recurring move across every doc is the same: replace opinion debates with structured signals tied to real users; balance attitudinal/behavioral/performance data; balance leading and lagging indicators; balance internal voices (team, stakeholders) with external voices (participants, customers); and tie every metric back to a UX outcome leaders can act on. Helio is the named in-house tool that lets these signals get captured in hours rather than months.

> **Note on the User Needs model.** Earlier compressed versions of Define described User Needs as a **7-layer UX Honeycomb** (Findable → Desirable). The current source-of-truth Define Overview v1.1 (Oct 25, 2025) and User Needs v1.1 (Oct 25, 2025) restructure this into **5 categories with 22 individual need types** (Basics, Trust, Personal, Impact, Feelings). The 22 individual need-type pages remain consistent with their earlier honeycomb-style framing; what changed is the category-level grouping. This skill follows the v1.1 five-category model.

> **Note on UX metric types.** Earlier compressed versions added a fourth "Perceptual" metric type. The current source-of-truth UX Metrics doc — v1.0, re-edited 2026-05-06 — explicitly defines **3 metric types only**: Attitudinal / Behavioral / Performance. This skill follows the 3-type taxonomy as canonical; "Perceptual" is no longer in the Define source.

## Glare | Define Overview v1.1

- **Define = the Credibility facet of Glare.** It is "the first light that cuts through the Fog" of indecision; everything in Measure, Focus, and Lead later builds on what gets defined here.
- **Five building blocks** (v2.3 — added Patterns 2026-05-11) with a one-line core question for each:
  - **User Needs** — "What do users actually need or hope to achieve?" Anchors design in real problems, not assumptions.
  - **Audience** — "Who are we really designing for?" Ensures empathy and precision; keeps data relevant.
  - **Patterns** — "What recurring situation keeps producing this behavior?" Recognizes the situation surrounding the signal before weak decisions scale.
  - **Collecting Data** — "Where does clarity come from?" Turns hunches into hard evidence early.
  - **UX Metrics** — "How do we know it worked?" Gives design credibility through visible proof.
- **Five user-need categories (foundational → aspirational):** Basics, Trust, Personal, Impact, Feelings. Each category groups four individual need types. Higher categories earn the right to the next; a broken Basic can't be rescued by a strong Feeling.
- **Audience principle:** "Design for everyone and you design for no one." A marketer tracks bounce rate; a PM tracks adoption — same product, different signals.
- **Collecting principle:** Skipping collection only delays clarity. One small signal saves weeks. Cited proof: a university navigation test produced a 41% increase in positive impressions before launch.
- **UX Metrics principle:** Metrics are "the grammar of signals." A 70% completion rate can settle weeks of debate.
- **Quick checks per block:** Does this solve a real user goal? Can you name 3 audience traits? What recurring pattern keeps showing up around this situation? What real input are you using (survey/test/analytics)? Which metric proves progress (completion, effort, satisfaction)?
- **Without Define:** needs are guesses, audiences vague, data missing, metrics hollow. **With Define:** hunches become signals, ideas become user-backed decisions.

## The five-category user-need stack (v1.1)

| Category | Core question | Design focus | Sample metrics |
|---|---|---|---|
| **Basics** | "Can I use it easily?" | Flow, clarity, access | Task completion, error rate, time on task |
| **Trust** | "Do I believe it works?" | Predictability, consistency | Credibility, bounce rate |
| **Personal** | "Does it fit my needs?" | Relevance, inclusion | Adaptability, comprehension |
| **Impact** | "Does it make a difference?" | Efficiency, results | Conversion, retention |
| **Feelings** | "Does it inspire me?" | Emotion, motivation | Sentiment, preference |

Each category contains four individual need types (22 total — see the User Needs reference for the full breakdown):

- **Basics** → Usable, Useful, Findable, Accessible
- **Trust** → Credible, Secure, Reliable, Intuitive
- **Personal** → Inclusive, Adaptable, Connected, Insightful
- **Impact** → Valuable, Sustainable, Efficient, Scalable
- **Feelings** → Desirable, Delightful, Engaging, Empowering

## Glare | Define, Audience v1.1

- **Audience defines who your signals come from and how much weight each voice should carry.**
- **Four primary audiences:** Project Team (intent; light continuous weight); Stakeholders (direction; medium-to-high); Customers (proof; highest weight); Participants (clarity; high during testing).
- **Internal voices guide; external voices validate.**
- **Five core attribute types:** Behavioral, Motivational, Contextual, Lifecycle, Demographic. Use 3–5 attributes total.
- **6-step define-and-measure flow for external audiences:** start with a question → identify customer vs participant → choose 3–5 attributes → map to UX metrics → collect and compare → check whether participant signals predict customer behavior.
- **The flow:** Project Teams form intent → Stakeholders align impact → Participants validate direction → Customers prove outcomes.

## Glare | Define, Patterns v1.0 (added 2026-05-11)

- **A pattern is a recurring situation where similar conditions repeatedly produce similar behaviors and signals.** Not a metric, dashboard, trend, persona, or isolated observation.
- **Situations create meaning.** The same behavior (e.g., long session duration) can signal engagement, confusion, hesitation, comparison, or cognitive overload — only the surrounding situation reveals which.
- **Four pattern types:**
  - **User Patterns** — hesitation during onboarding, abandoning high-effort flows, comparison paralysis, repeated misunderstanding, low-confidence purchasing.
  - **Workflow Patterns** — endless review cycles, late validation, siloed optimization, repeated decision reopening, weak cross-functional alignment.
  - **Signal Patterns** — engagement rises while trust declines, usability improves while retention weakens, completion increases while effort grows, AI adoption rises while confidence falls.
  - **AI Workflow Patterns** — faster production with weaker evaluation, shallow iteration loops, overproduction without prioritization, AI-generated consistency masking weak thinking.
- **Patterns and UX Metrics:** patterns reconnect metrics to the surrounding situation. The four metric lenses (By Type, By Stage, By Time, By Engagement) each reveal a different kind of pattern.
- **Why patterns matter more now:** AI accelerates output, not understanding. Faster generation without pattern recognition scales weak decisions faster than teams can fix them. The goal is **directional confidence while work is still evolving**, not perfect certainty.

## Glare | Define, Collecting v1.1

- **Collecting = turn raw input into usable signals.**
- **Cadence pattern across all "-ing" pages:** Define → Capture → Connect.
- **Four feedback types:** View user data (analytics), See what users do (task success/first-click/heatmaps), Sense what users like (desirability/satisfaction surveys), Hear what users say (surveys/interviews/in-product prompts).
- **Five-step collection process:** Start with Intent → Choose Your Stack (Research vs Design; modes: Exploratory / Evaluative / Comparative) → Identify the Approach → Apply the Techniques → Connect and ready your data.
- **Three-tier sharing model (v1.1 added):** Project-Level Feedback / Cross-Team Insights / Leadership Rollups. Always cite techniques + audience + metrics.
- **Five Design Stacks:** Website, Mobile App, Product, E-commerce, Marketing.
- **Twelve techniques:** First Click Testing, Task Success Rate, Time on Task, A/B Testing, Multivariate Testing, Heatmaps, Clickstream Analysis, Web Analytics, Conversion Rate Analysis, Eye Tracking, Card Sorting, Surveys & Questionnaires.
- **Common research stacks:** SUS, SEQ, PURE, SUMI, CES, CASTLE, NASA-TLX, WAMMI, PSSUQ, QUIS, UEQ, UX-Lite, SUPR-Q, NPS, L-DERLY.

## Glare | Define, UX Metrics v1.0 (re-edited 2026-05-06)

- **A UX metric quantifies how users feel and behave.**
- **Three types (canonical taxonomy):**
  - **Attitudinal** (how users feel): Brand Score, Desirability, Expectations, Feeling, Helpfulness, Trust, Loyalty, Satisfaction, Reaction, Sentiment, Usefulness
  - **Behavioral** (what users do): Completion, Comprehension, Effort, Engagement, Frequency, Intent, Success, Usability
  - **Performance** (efficiency/accuracy): split into Marketing (Avg Time on Page, Avg Session Duration, Pages per Session, Bounce Rate, Exit Rate, Device Type, Event Tracking), eCommerce (Engagement, Abandonment Rate, Bounce Rate, Store Sessions), and Product (Stickiness, Activation Rate, Feature Usage, Time to Activate, Retention Rate, Click-back Rate)
- **Helio integration (called out in v1.0 re-edit):** Collect attitudinal metrics as leading indicators in Helio before your product ships. Collect behavioral metrics as leading indicators before analyzing post-launch performance. Helio signals serve as both predictive indicators and proxy metrics, validating ideas in a controlled environment before launch.
- **Four principles for choosing metrics:** Easy to Understand · Good for Comparison · Use Rates or Ratios · Focus on Behavior.
- **Four critical comparisons:** Vanity vs Actionable · Qualitative vs Quantitative · Exploratory vs Reporting · Correlated vs Causal.
- **Four lenses:** By Type · By Stage (Predictive/Proxy/Analytics) · By Time (Leading/Lagging) · By Engagement (Needs/Behavior/Activity).
- **Quick checklist (9 items, ninth added in 2026-05-06 edit):** Can it be explained in one sentence; comparable; a rate not a count; behavior-grounded; actionable; pairs *what* with *why*; fits timing; balances leading/lagging; **builds momentum instead of slowing it down**.

## Key terms

- **Glare** — the overall framework. Define is its first facet ("Credibility").
- **Fog** — the state of indecision Glare is designed to cut through.
- **Define** — the credibility-building first facet. Four blocks: User Needs, Audience, Collecting, UX Metrics.
- **Signal** — a measurable, trustworthy piece of evidence (vs raw "data"). The unit of credibility in Glare.
- **Design Signal** — what data becomes when patterns make sense; evidence turning into direction.
- **Helio** — the in-house testing platform; gives signals in hours not weeks; 1M+ participants run through it. Used for first-click tests, preference tests, surveys, usability tests; serves as predictive and proxy metric channel before launch.
- **Needfinding** — Stanford-born practice for surfacing real (not stated) needs.
- **Five User-Need Categories** — Basics, Trust, Personal, Impact, Feelings.
- **22 Individual User-Need Types** — Usable, Useful, Findable, Accessible · Credible, Secure, Reliable, Intuitive · Inclusive, Adaptable, Connected, Insightful · Valuable, Sustainable, Efficient, Scalable · Desirable, Delightful, Engaging, Empowering.
- **Four Audiences** — Project Team (intent), Stakeholders (alignment), Participants (clarity/validation), Customers (proof).
- **Five Attribute Types** — Behavioral, Motivational, Contextual, Lifecycle, Demographic. Use 3–5 to define a testable group.
- **Three Modes of Learning** — Exploratory, Evaluative, Comparative.
- **Three UX Metric Types** — Attitudinal, Behavioral, Performance. (No Perceptual; that v1.1 addition was reverted in the 2026-05-06 source edit.)
- **Four UX Metric Lenses** — By Type, By Stage (Predictive/Proxy/Analytics), By Time (Leading/Lagging), By Engagement (Needs/Behavior/Activity).
- **Define → Capture → Connect** — the cadence pattern across all "-ing" pages in Glare.
- **Four research-instrument families** — Usability & Ease (SUS, SEQ, PURE, SUMI), Effort & Workload (CES, CASTLE, NASA-TLX), Satisfaction & Experience (WAMMI, PSSUQ, QUIS, UEQ, UX-Lite, SUPR-Q), Trust & Loyalty (NPS, L-DERLY).

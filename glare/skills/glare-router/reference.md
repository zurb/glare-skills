## Three named flows that have order

When the user is mid-flow, route by step rather than by section.

### SIGNAL (Design Review) — six steps in order

`Surface → Identify → Ground → Navigate → Align → Lock`

If the user names which step they're on, go straight to that letter's skill (`glare-review-surface`, etc.). If they're stuck between two letters, route to the *current* one — the next letter's skill is the natural handoff. If they have a transcript and want to score the whole arc, route to `glare-review-run-transcript` (which then uses `glare-review-rubric`).

### Decision Map — four areas in flow (loop, not line)

`Define → Measure → Focus → Lead → (back to Define)`

If the user names which area they're stuck in, go to that parent. If they're on a handoff (e.g., "we have findings but don't know how to choose"), route to the *next* area's parent (`glare-focus`). Don't fight the loop — outcomes feed the next Define cycle.

### Measure — four moves in arc

`Concepts → Hunches → Questioning → Findings`

If the user is forming a believe-statement → `glare-measure-hunches`. If they're trying to draft research questions → `glare-measure-questioning`. If they have data and need to translate it → `glare-measure-findings`. If they're upstream of all of it (anchoring intent) → `glare-measure-concepts`.

## When ambiguous — the one-question protocol

If the diagnosis is genuinely 50/50 between two very different sections, ask ONE question. Common useful questions:

- "Is this about a meeting you just ran, or a decision you're about to make?" — disambiguates `glare-design-review` vs. `glare-decision-map`
- "Do you have data already, or are you trying to figure out what to test?" — disambiguates `glare-measure-findings` vs. `glare-measure-questioning`
- "Are you trying to pick a direction, or trying to prove the direction worked?" — disambiguates Focus vs. Lead
- "Is this about your own decision, or about how the org handles decisions in general?" — disambiguates a Decision Map area vs. `glare-design-assessment`

Then route. Don't ask twice.

## What the router never does

- Recommends a list of skills. (One.)
- Recommends a skill that isn't in the catalog of 54.
- Tries to do the destination skill's work itself.
- Re-routes a user who is already productive in their current skill.
- Lectures the framework before routing. If they want the framework, the right route is `glare-get-started` or `glare-how-glare-works`.
